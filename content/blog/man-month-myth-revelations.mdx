到今天，大约是我开始 vibe coding 的第一个整年。一切的起点，是厦大小学期的一门 Python 程序设计实践课，还有一份不知道从谁口中听来的 GitHub 学生认证包。我打开 Visual Studio Code，用上内置的 Copilot，模型是 GPT-4o。

今年的小学期也刚刚结束。回头看这一年，尤其是 Coding Agent 的这一年，变化实在太快了。

## 一、Tripy

梦开始的地方，是一个叫 Tripy Web 的项目。

我给项目取名总要选很久。说是想让每个名字都有一点意义，可能也就是选择困难。Tripy 里的 tri 是三，因为课设小组有三个人；py 是 Python。连起来，Tripy，就这么定了。

2025 年六月底，我对做项目还没什么概念。用着 ChatGPT 免费账户那十来条消息的额度，我准备问 4o：“我要做一个 Python 程序设计课设……”

字打到这里，停住了。我发现自己不知道下一句该说什么。项目是什么，为什么还要分前端和后端，接下来需要做什么，我都不知道。

最后还是把这句话发了出去。4o 推荐了几个方向，我和 partner 选了个人博客。

那时我还没怎么接触提示词这些讲究。Claude Code 很热闹，我舍不得充值；Codex 我也还没用上。现在回忆起来，已经忍不住说“那个年代”了。一年前都能叫年代了🤣。

摸索了一会儿，我发现 Copilot 里面居然也有 4o，还能帮我执行命令。我去做了学生认证，拿到不少额度，就开始让它搭博客。

具体怎么开头的，我已经记不清了。只记得它最先给我的是一个 HTML 页面，上面有账号、密码两个输入框，还有注册、登录按钮。很原始，但我没动手写代码，这个网页就出现在面前了。那一刻，真有一种草履虫爬出火山底的感觉。

高兴完才发现，它给我的也就只有这个页面。离我想要的博客系统，还差得很远。

后来就是磕磕碰碰地往前做，刷到什么就想用什么。看见 FastAPI 想换 FastAPI，觉得 Django 也不错，又想试 Django，前端还想换成 Vue。当时的 Copilot 支撑不了我这样折腾，让它处理 Vue、Vite 编译时的报错，都经常卡住。现在看起来一句话就能交出去的重构，当时让我吃了不少苦头。

这也留下了一点后遗症。Git 我自己操作，前后端开发服务器自己启动。稍微复杂一些的事情，我就不敢交给它。

我还没摸清它能做什么，就已经想让它帮我把整个项目做完了。当时确实有点空中楼阁的意思。

## 二、搬到终端里

八月，GPT-5 来了。到了九月，我在美区商店充值了 20 美元，订阅 ChatGPT，开始认真用 Codex。印象里，那时 CLI 的版本号大约是 0.36。

Codex 当时的声量没有 Claude Code 那么大，但它带着我做了第一个外包项目的后端：[Suanxian](/works/suanxian)。

赶上 Cloud 的促销期，可以放开了用。它会克隆 GitHub 仓库，配置环境，改代码，最后给我一个 PR。想起来很合理，实际等起来却很漫长：模型慢，克隆、装环境、网络传输又要花时间，最后处理 PR 的体验也不太顺。

用着用着，我甚至觉得，比起在网页版聊天、来回复制代码，好像就多了一个 PR 按钮。中间发生了什么，结果怎么样，我很难及时看到，也很难顺手接着改。

但它可以无限用啊。我一口气扔了十几个并行任务出去，最后把 PR 一锅乱炖，合进了外包项目的代码库。

后来我觉得，用这些工具的一份经验，就是烧 Token 的同时，也在摸清模型和 harness 的脾气。模型会怎么理解我的话，外面这层负责工具调用、执行和上下文的程序又会怎样影响它，都是用着用着才知道的。当时如此，现在也一样。

Cloud 最让我难受的地方，是反馈太远了。我逐渐把重心移到 Codex CLI，想在自己的项目里直接看着它做事。

CLI 对新人当然不友好。光是 Command Line Interface 这几个字，就够吓跑一些人。我庆幸自己忍了下来，可能也因为当时要学的斜杠命令没那么多。

我先学会了 `/init`，让它给项目建一份 AGENTS.md；再往后就是切模型、调思考强度、退出。还有 `/status`，看剩余额度。这条命令用得尤其熟练。

那时我还向一位文科朋友推荐过 Codex。对方大概很难理解，我为什么能每天泡在一个终端界面里。我也想过很多次，该怎样说明它和 ChatGPT 的区别。最后通常就说：把聊天搬到终端里了，你照样输入需求，它可以读你的文件、操作电脑。

在 CLI 里输入一句话，它会自己读代码、跑命令，再根据输出往下做。我终于能看到这些事情接着发生，也开始有了一点所见即所得的感觉。

当然，早期仍有让人不放心的地方。比如开发服务器开起来以后，一直占着端口，后台进程又不太好找。我也遇到过强制退出窗口后，进程还留着的情况。它启动了什么、最后留下了什么，我还得自己留意。

到 2025 年底，这些问题逐渐没那么困扰我了。5.1、5.2，以及后来的 Codex 模型，让我开始敢把更多命令交出去。后台进程在界面上更容易找到了，退出时也多了提醒。

我想，这是模型、harness 和交互设计一起往前走的结果。社区里也在聊 Prompt Engineering、Context Engineering，聊 Plan 模式，聊怎样让 Agent 更好用。我会看 GitHub 上的讨论，看产品经理怎么回复，再等着这些东西进到自己手上的版本里。

那是我最狂热的时候。每一份 release note 都认真读，生怕漏掉一个新功能。

## 三、桌面端

2026 年初，5.3 Codex 和 Codex Desktop 陆续到来，我也第一时间下载了桌面端。

刚开始用，确实觉得有些别扭。UI 里可以 commit、push，却找不到 pull；可以看改动的 diff，又没有文件树。它卡在传统 IDE 和 CLI 之间，我一时说不清它想让我怎么用。那时我的评价就是：不伦不类。

后来更新多了，线程切换、终端管理、新建任务，都可以顺手点出来。我用桌面端越来越多，也更认同这个方向。终端用习惯了当然很好，但要把它推荐给身边的人，GUI 还是自然得多。

查看剩余额度，当然也变成了顺手点一下。

这一年追着更新用下来，我对 Codex 团队也积累了一些信任。我会想，他们应该最懂自家的模型。我平时用 ChatGPT 的模型多，继续用 Codex 就成了一件很顺手的事。

## 四、放手之后

到了 5.4、5.5 那段时间，胶水代码和过度防护开始经常出现在我的视野里。我自己也会遇到：Vibe 了一大段，功能看着能跑，底下的设计却已经和最初想的有了距离。

有一种情形尤其熟悉。我先让 Codex 画出一个满意的 workflow，然后说“完整完成”。它做一轮，停了。我追问还有没有遗漏，它说还有一部分；再问，又还有一部分。

后来有了 Goal。我的理解是，它会持续保留一个目标，做完一轮再判断有没有完成；没完成，就在后续轮次里继续带着这个目标往下做。即使中间压缩了上下文，目标也还会被重新带进来。社区里很快出现了跑几个小时、甚至几天的截图。

我也试了，然后遇到过一次循环。它要搭自动测试，需要拿到某个 CLI 工具的 Token，而这一步必须由我授权。授权没完成，测试搭不起来，Goal 也就一直没完成。它反复被唤起，继续尝试，停不下来。

现在回头看，我当时也没有仔细想过，它遇到这种情况该怎样退出。用 Agent 久了，提示词越来越短，越来越习惯只说一个大概目标，这件事很容易漏掉。

所以我目前还是更愿意把 Goal 用在 E2E 验证这类事情上：要操作什么、怎样算通过，我心里比较清楚。至于让它持续构建、开发一个项目，我还没有那么放心。

过度防护的问题，到现在我也没有找到周全的办法。有时只是最初对一个功能多强调了一点防护，后面就一路长出很多额外处理和测试。等我注意到，测试集已经膨胀得很大了。

我想把限制写进 AGENTS.md，又会担心上下文压缩后，它还能记住多少。每轮都再提醒一次，也担心自己干扰了模型原本的判断。尝试了不少办法，仍然需要边用边看。

人对项目把关得越细，需要跟进的事情就越多。步步 review，自然很难有放手让它去做的轻松。可一旦放开，自己参与的决策点又会变少，到了某个时候，甚至有一点抽卡的感觉。

我想，人和 Agent 如果能在重要的地方保持信息同步，合作会舒服很多。至于同步到什么程度，我还说不清楚。业务该理解的部分，仍然需要花时间理解；我至少得知道，现在的项目在往哪里走。

和 5.6 Sol 讨论方案时，这个问题又有了另一种表现。它常常一口气给我很多信息，事实和它自己的判断混在一起。我一边读，一边决定哪些接受、哪些反驳，还要把有用的信息记下来。

等我提出异议，它又重新写了一套方案。有时顺着我改得太快，我还得回头检查，前面那些信息有没有漏掉。讨论了一大圈，人已经很累，决定却还没做清楚。

目前对我有用的办法，一个是直接要求它：“输出关键信息，并指出决策点。”另一个是把项目的文档维护起来。现在能在 Codex 里看 Mermaid，我就对着流程图想，事情在哪一步，需要我决定什么，比来回翻长段对话清醒一些。

有时我会花二三十分钟，认真写一份提示词，把自己想得到的方向和限制尽量说清楚，再交给它。这样它通常也能跑得久一点，我不用一直守着补充。

我思考完，轮到它。自己终于能喘息片刻。

## 五、随时问一句

还有一个我困惑了很久的小问题：为什么早期 Codex 一直把 archive 放得那么明显，delete 却迟迟不好找？

我有时只问一个很简单的问题，问完就想删。侧边栏留着它，总觉得多了一件没收拾的东西。后来也懒得纠结，就安慰自己，本地攒了那么多对话，再多留一些，以后可以美美地把自己蒸馏成 Skill。

等 Side Talk 和 Task Tool 出现，我对这件事的感受才变了。删除后来也有了，但我已经很少特意去找。

以前我用 fork，通常是在聊过一轮信息之后，分出去做另一件事。Side Talk 则让我能在任务进行中就插一句话。比如它正在跑一个命令，我看着不太对劲，可以马上在侧边问：“你现在为什么要跑这个命令？”

这个时机对我很有用。我可以趁着疑问还在的时候，把它问清楚。

侧边对话是临时的，也不用给侧边栏再留一条记录。我用到后来，主任务和侧边对话的思考强度也可以分别调了。于是随口问一句、临时试一个想法，都轻松了很多。

侧边探索完，还能把得到的信息传回主任务，让它接着做。这样我可以先把自己的疑问想清楚，再决定哪些信息值得带回去。

慢慢地，我也没那么惦记删除了。连网页版里的一些对话，我都会顺手归档。之前总想把对话列表收拾干净，那点心理负担确实轻了不少。

## 六、把几台电脑连起来

以前别人问我，小龙虾这类 Agent 有什么值得用的，我经常举一个例子：电脑上放了个文件，出门后突然要用，就在手机上发条消息，让它找出来发给你。

持久化部署在那里，随时能叫它做事。这是我当时很喜欢的一点。

后来用上 Remote Control，我开始把这件事放到自己的几台设备上想。公司的电脑、美国的 Linux 服务器、不知道扔在哪个角落的 Mac mini，都可以留着干活，我从手上的设备给它们发任务。

再配合 Tailscale，把设备放到同一个内网里，通过 MagicDNS 找到机器、做 SSH，就能处理更多事情，机器之间的 SSH 也可以走内网。我可以在其中一台机器上挂容器，也可以和 partner 共用一套预发布环境，让 CD 往同一台机器上部署。买来的 VM 装好 Codex，以后想配什么服务，也能从另一台设备接着操作。

我不用一直坐在正在干活的那台电脑前面了。

回头看，Codex 一直在做给人用的交互，也一直保留着能从 CLI 调用的能力。走到 Remote Control，再连上网页里的 Work 和原来的 Cloud，这些东西在我的使用里逐渐接上了。

这时再想起一年前那个等得人着急的 Cloud，我才觉得，最初设想的那种远程工作，终于有了我愿意一直用下去的样子。

Computer Use 也让我做了不少以前没想过能直接交出去的事。配合 5.6、内置浏览器和已有的登录状态，我可以让它打开工作平台，在页面上操作。要改前端，就对着组件批注，指给它看。

我现在做一些前端 E2E 验证，会直接让它打开页面、点击、填写、看结果，专门写 Playwright 脚本的次数少了。客户端和移动端的调试也开始能这样做，尤其是 Suanxian 的小程序。

我以前经常需要自己接过鼠标，走完这些步骤再把结果告诉它。现在它能直接做其中不少操作。知道这里还用到了无障碍接口时，我觉得挺有意思，没想到会这样接上。

## 七、在同一个对话里继续做事

5.6 那段时间，我开始用 Ultra。最初的感觉有些机械、生硬，用久了，反而是它在长对话里的表现让我意外。

我一直想弄清它的子代理策略。当时我的理解是，在较高的思考强度之外，Ultra 还带来了一些调度上的变化。我也想过，能不能在低一些的思考强度下使用类似策略。不过具体怎样实现，我掌握的信息还不够。

那时我能用的上下文从 372K 缩到了大约 272K。压缩会更频繁，我自然担心信息丢失。可实际连续做了两周项目，Codex 的表现给了我很强的安全感。

同一份工作，我可以一直在一个对话里接着做。不同机器的连接方式、服务配置、前面讨论过的事情，还能继续用得上。至少在这些任务里，我没有频繁重讲背景的负担。

有一次工作跨了两个仓库、两台开发机、一个数据库，还有三四份外部文档。内容已经很多了，它到了需要判断的地方，仍然能说清楚几处信息之间的关系，给出让我认可的决定。

我第一次在 Claude Code 里用 Opus，让它叫两个 Sonnet 去搜集信息时，也有过类似的感觉。这种相似很主观，主要就在于主任务拿到信息之后，那几次判断让我觉得清醒。

后来我也去翻过自己看到的 Claude Code 工具提示词，留意到其中对横向、广范围探索使用子代理的引导。Ultra 具体怎样调度，我仍然不清楚，但它在这些跨仓库、跨机器的任务里，确实让我愿意继续试。

在这之前，我还真没想过，一个不到 1M 上下文的对话，可以让我这样一直做下去。

当然，Ultra 的 Token 也用得很快。

Tibo 是大恩人，时不时 reset 一下额度。但重置完，我照样会频繁点开看看还剩多少。用不完会惦记，用完了也难受。

对于五小时限额，我一直更倾向于让用户自己管理额度。大家都是成年人了，什么时候多用一点，自己安排就好。看着一次次 reset，我甚至会脑补这么一段：

> Altman：Tibo，做一下压测。  
> Tibo：Reset。

## 八、入口

这一年还有个让我觉得很有意思的变化，外部服务也在陆续做 CLI。上到飞书，下到瑞幸，连点咖啡都有 CLI 了。挺抽象的。

这些服务接进来之后，我在 Codex 里能做的事情就又多了一点。再加上 MCP、Skill，以及 Work 和 Chat 之间的衔接，在网页版里做的调研，也可以接着交给 Codex 去执行。我已经很习惯这样用，没觉得中间有什么突兀。

反而是自己的输入速度，开始让我在意了。想说的事情很多，打字有时跟不上。在安静的办公室里，我又实在接受不了对着电脑语音输入。这件事还得想想办法。

文章写到这里，是 7 月 23 日。

这一年，我已经烧掉了 20B 多的 Token。从课程里那个只有登录表单的网页，到现在几台电脑上一起推进的工作，Agent 已经成了我连接计算机和世界的一个入口。

我还有更远的计划。下一份实习，下一个项目，再远一些，也许是下一个国家。

我想，它也会陪着我一起去。
